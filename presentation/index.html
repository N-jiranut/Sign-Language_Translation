TSL Assist: Thai Sign Language Translation

ระบบแปลภาษามือไทยแบบเรียลไทม์ผ่านกล้องเพื่อเคาน์เตอร์บริการ

"A camera-based assistive system that translates isolated Thai Sign Language words into real-time text and speech for service counters."

(ระบบกล้องอัจฉริยะที่แปลท่าทางภาษามือไทยเป็นข้อความและเสียงพูดทันที เพื่อแก้ปัญหาการสื่อสารในจุดบริการ)

🎯 Core Goal

ขจัดอุปสรรคในการสื่อสารเร่งด่วน ระหว่างคนหูหนวกและเจ้าหน้าที่บริการ

⚡ Key Tech

MediaPipe Tasks (112 Dims) + PyTorch GRU / Random Forest + Desktop GUI

🏢 Scope Context

มุ่งเน้นจุดบริการ เช่น โรงพยาบาล แผนกต้อนรับ และสถานีตำรวจ

Problem Background

1. The Real-World Problem

ทำไมการสื่อสารที่เคาน์เตอร์บริการจึงเป็นเรื่องท้าทายสำหรับคนหูหนวก?

⚠️ จุดติดขัดหน้างานจริง (The Friction)

  • ภาษามือคือภาษาแรก: ภาษาไทยเขียนมีไวยากรณ์ต่างกัน การเขียนกระดาษสื่อสารจึงสร้างความกังวล
  • ล่ามภาษามือขาดแคลน: ไม่สามารถอยู่ประจำทุกจุดบริการได้ตลอดเวลา
  • ความล่าช้าในจุดสำคัญ: การซักประวัติเบื้องต้นที่เคาน์เตอร์ รพ. หรือจุดบริการใช้เวลานาน

💡 คำถามวิจัยของโครงงาน (The Hook)

"เราจะสร้างระบบกล้องราคาประหยัด ที่จดจำคำศัพท์สำคัญ 10-15 คำ แล้วแปลเป็นเสียงพูดให้คนทั่วไปเข้าใจทันที โดยไม่ต้องสวมใส่อุปกรณ์เซนเซอร์ได้หรือไม่?"

มุ่งแก้ปัญหาใน บริบทเฉพาะทาง (Focused Domain) เพื่อความแม่นยำสูงสุดในชีวิตประจำวัน

Project Scope

2. Project Scope & Vocabulary

กำหนดขอบเขตและเป้าหมายของระบบอย่างชัดเจน

✅ สิ่งที่ระบบครอบคลุม (In Scope)

  • ประเภทท่าทาง: คำเดี่ยวหรือวลีสั้น (Isolated Signs)
  • คลังคำศัพท์ปัจจุบัน (10 คำ):
    Done, Dont_like, How, Me, No, Thank, Tomorrow, Worry, Yesterday, You
  • ตำแหน่งผู้ใช้: นั่งหน้ากล้องห่าง 90 ซม., กล้องสูง 161 ซม., ก้ม 20°-30°
  • รูปแบบผลลัพธ์: ข้อความบนจอ + เสียงสังเคราะห์ (Text-to-Speech)

🚫 นอกขอบเขต (Out of Scope)

  • การแปลประโยคยาวต่อเนื่อง (Continuous Signing): ด้วยความเร็วธรรมชาติ
  • ไวยากรณ์ภาษามือระดับประโยค: (Sentence-level Grammar Parsing)
  • การแสดงสีหน้า (Facial Expression): ใช้เฉพาะท่าทางของมือและตำแหน่งแขน/ลำตัว

Technical Innovation

6. Why It Works With 10 Samples

เคล็ดลับทางวิศวกรรมข้อมูลที่ทำให้โมเดลแม่นยำสูงแม้ข้อมูลกะทัดรัด

1. Scale-Invariant Normalization (112 Dims)

  • Pose 13 จุด (26 ค่า): ยึดกึ่งกลางไหล่เป็นจุดกำเนิด (0,0) และหารด้วยความกว้างของไหล่ (Shoulder Width)
  • Hands 21 จุด x 2 (84 ค่า): ยึดข้อมือเป็นจุดกำเนิด และปรับขนาดด้วยระยะจากข้อมือถึงโคนนิ้วกลาง
  • Presence Flags (2 ค่า): บ่งบอกว่าตรวจพบมือซ้าย/ขวาหรือไม่
  • ผลลัพธ์: ข้อมูลจะไม่แปรผันตามระยะนั่งใกล้-ไกล หรือสรีระร่างกายของผู้ใช้

2. Temporal Resampling (24 Frames)

  • ไม่ว่าผู้ใช้จะทำท่าเร็ว (1.0 วินาที) หรือช้า (2.0 วินาที)
  • ระบบใช้ Linear Interpolation ปรับความยาวเป็น 24 เฟรมคงที่เสมอ
  • ขจัด Noise ด้านความเร็วในการเคลื่อนไหวออกไป 100%
  • ผลลัพธ์: โมเดลโฟกัสเฉพาะ "ลำดับวิวัฒนาการของท่าทาง" จึงเรียนรู้ได้ไวมาก
Problem Solving

7. Lessons Learned & Engineering Challenges

ปัญหาหน้างานจริงที่พบระหว่างพัฒนาและแนวทางแก้ไขเชิงระบบ
ความท้าทายที่พบ (Blocker) ผลกระทบต่อระบบ วิธีการแก้ไขทางวิศวกรรม (Solution)
ฝ่ามือซ้อนทับกัน (Hand Occlusion)
เช่น ท่าไหว้/พนมมือ		 MediaPipe ตรวจจับมืออีกข้างไม่เจอ ทำให้ข้อมูลขาดหาย ปรับมุมกล้องก้มลง 20°-30° เพื่อให้เห็นหลังมือทั้งสองข้าง และเว้นระยะฝ่ามือ 1-2 ซม.
ระยะห่างและตำแหน่งนั่งไม่คงที่ โครงกระดูกหลุดขอบจอ หรือพิกัดเพี้ยน สร้าง Camera Calibration HUD ตรวจเช็คกึ่งกลางตัวและระยะกางศอก (Elbow Span)
การระบุจุดเริ่มต้น-สิ้นสุดของท่า ท่าทางปนกับจังหวะพักมือ ทำให้โมเดลเดาผิดตลอดเวลา ออกแบบ Chest Ready Line State Machine ยกมือค้าง 0.35 วิเพื่อเริ่มบันทึกอัตโนมัติ
